## 2. Назначение, вход и выход

Модель прогнозирует цену бриллианта по его характеристикам. Предполагаемые пользователи — оценщики и сотрудники ювелирных магазинов. Прогноз служит ориентиром при подготовке предложения клиенту; окончательную цену определяет специалист. Проект реализует обучение и API, а работа магазина показана как возможный сценарий применения.

`POST /predict` принимает девять обязательных полей:

| Поля | Содержание |
| --- | --- |
| `carat` | Масса, караты |
| `cut`, `color`, `clarity` | Качество огранки, цвет и чистота |
| `depth`, `table` | Относительная глубина и ширина площадки, % |
| `x`, `y`, `z` | Длина, ширина и высота, мм |

Дополнительно вычисляются `volume = x*y*z`, `density = carat/(volume+0.001)` и `depth_to_width = depth/(x+0.001)`. Это расчетные признаки; `volume` приближает объем, а `density` не является физической плотностью.

Ответ содержит `predicted_price` — оценку цены с округлением до двух знаков — и `message`. Единицы соответствуют обучающим данным: для Kaggle Diamonds это доллары США. Интервал неопределенности не рассчитывается.

## 3. Факторы качества

Точность зависит от диапазона массы, категорий качества, ошибок измерений и сходства новых данных с обучающими. Дата продажи, регион, сертификат и рыночная ситуация в признаках не представлены.

## 4. Метрики

| Метрика | Назначение |
| --- | --- |
| RMSE | Ошибка в единицах цены с повышенным весом крупных отклонений |
| MAE | Средняя абсолютная ошибка в единицах цены |
| R² | Доля объясненной вариации цены; ближе к 1 — лучше |
| MAPE | Средняя абсолютная относительная ошибка, % |

Для RMSE, MAE и MAPE меньшее значение лучше. Порог приемки качества не установлен.

## 5. Оценочные данные

Для оценки выделяются **20%** записей, в текущем запуске — **100 строк**. Разбиение случайное, `random_state=42`. Тестовые строки не используются при обучении.

## 6. Обучающие данные

В работе использовался реальный **Diamonds Dataset с Kaggle** — характеристики бриллиантов и их цены. После очистки **80%** записей используются для обучения, целевая переменная — `price`. CSV размещается в `data/raw/diamonds.csv`.

Текущий локальный CSV содержит **500 строк** и совпадает со встроенным демонстрационным набором проекта; обучающая часть — **400 строк**. Приведенные ниже метрики относятся к этому запуску, а не к полному Kaggle Dataset.

Подготовка включает удаление дубликатов, пропусков и некорректных измерений, добавление расчетных признаков. Внутри `Pipeline` числовые признаки заполняются медианой и масштабируются, категориальные — заполняются модой и кодируются через One-Hot Encoding. Эти преобразования обучаются только на train.

## 7. Результаты

Результаты текущего запуска `run_pipeline.py` на 100 тестовых строках из [models/metrics.json](models/metrics.json):

| RMSE | MAE | R² | MAPE |
| ---: | ---: | ---: | ---: |
| 589,59 | 483,14 | 0,9631 | 7,06% |

Средняя абсолютная ошибка — 483,14 в единицах цены, средняя относительная — 7,06%. Это средние значения по тестовой выборке, а не гарантия точности отдельного прогноза. Метрики также доступны через `GET /model/info`.

Для повторного запуска: `python run_pipeline.py`. Для оценки на Kaggle Dataset нужно заменить текущий CSV исходным датасетом и повторить запуск.

## 8. Этические аспекты

Признаки не содержат персональных данных. Ошибочная оценка может привести к завышению или занижению цены, поэтому перед сделкой результат должен проверить специалист. Модель не определяет подлинность и происхождение камня.

## 9. Ограничения и применение

- Перед применением на текущем рынке нужно проверить качество на актуальных данных сделок.
- Прогнозы для редких категорий и значений вне обучающего диапазона могут быть ненадежны.
- API проверяет положительность чисел и непустоту строк, но не все допустимые диапазоны и категории.
- При обновлении данных нужно повторить обучение и обновить метрики. Функции мониторинга есть, автоматическое переобучение не настроено.
